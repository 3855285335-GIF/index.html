# Chatter 自动检查

**规矩：改完代码先跑一遍，全部 ✅ 才推送；有 ❌ 先修。**

这些检查只在本机跑：用一个“假手机”（jsdom）把仓库里的 `index.html` + `app.js` 原样跑起来，Supabase 换成内存里的假数据库。不联网，不碰线上数据。

## 怎么跑

```bash
cd tests
npm install          # 第一次要装依赖
npm test             # 全部跑一遍，约 1.5 分钟
npm run quick        # 跳过两个要等十几秒的，约 40 秒
```

最后一行显示 `✅ 全部通过` 才能推送。

## 检查了什么

| 检查 | 防的是什么 |
|---|---|
| 代码检查（app.js、sw.js） | 拼错变量名、重复定义、写错的判断这类低级错误 |
| 收消息 | 聊天开着时新消息不出现；聊天关着时预览或未读不对 |
| 打开聊天 | 本机缓存和服务器新消息合并后顺序错乱、丢最新一条 |
| 不闪（3 项） | 刷新时整片重画：气泡重新弹、图片和头像重新加载 |
| 编辑（2 项） | 对方改消息不提示或提示两次；预览被旧消息顶掉；自己的消息能改多次；没发编辑推送 |
| 推送 | 本机误以为对方在线就不推；对方正在看还推 |
| 群消息 | 实时到达没有横幅或横幅不带群名；同一条重复提示 |
| 国内模式 | 自己另一台设备发的群消息被当成新消息；别人发的不加未读 |
| 群链接卡片 | 卡在“加载中”；取不到时无限重试 |
| 关聊天存缓存 | 发送失败的消息被存进缓存，重开后变成删不掉的幽灵消息 |
| 图片 | 不先显示小图；网络不好被误报“已被清理”；网络恢复不自动重试 |
| 登录 | 网络失败不自动重试；密码错却重试 |
| 注册 | 网络差时多发一次查重请求；错误显示英文、不说哪一步；重名但上次其实注册成功时进不去 |
| 添加到桌面 | iPhone 各版本 Safari、微信里打开、已经是桌面应用时给错指引 |
| 返回手势 | 主页面垫假历史（边缘滑出现点不动的旧截图）；“前进”时出现假聊天页又弹回 |
| 登录设备 | 菜单打不开 |
| 群消息补推 | 推了一部分后不再问（当时在线、随后离开的人收不到）；服务器说“都推过了”还一直问 |
| 退出其他设备 | 没让服务器删推送登记、没作废其他设备的登录凭证；发起的这台把自己踢掉；服务器还没更新时出错；查不到时误踢 |
| 来电 | 来电界面不弹、拒绝后不关 |
| 网页搜索 | 点放大镜不下载搜索；营销号没隐藏、置顶不在前；简洁阅读把脚本带进来；返回退不回去；在搜索里打开聊天被盖住 |
| 半屏 | 键盘收起后页面停在半屏 |

## 可选：真浏览器测试（Chromium）

先装一次：`npm i --no-save playwright && npx playwright install chromium`

```bash
node start-test.js   # 白屏保护 + 自动更新，约 2 分钟
node sw-test.js      # 后台小助手（sw.js）缓存
```

`start-test.js` 检查：
- 白屏保护：主程序下载失败、启动时报错、启动图收起后才报错、页面空白——都要出现“重新加载 / 清除缓存后重开”；正常打开、正常使用中偶发报错不打扰；
- 清除缓存：只清会话/消息/群/图片缓存，登录、主题、气泡、依赖库都保留；网址加 `?reset=1` 也能清；
- 自动更新：刚打开发现新版自动换上并提示一次；正在用时不打断，回到前台才换，换完回到刚点的通知；线上一直给旧页面时最多换 2 次，不会无限刷新；手动“检查更新”有提示。

`sw-test.js` 检查：程序文件和看过的图片有没有存进手机；服务器连不上时能不能照样打开；网页更新后是不是第一次打开就用上新版。

## 可选：SQL 试跑（不碰线上数据库）

```bash
npm i --no-save @electric-sql/pglite@0.2.17
node sql-1117-test.mjs
```

在内存里的 PostgreSQL 里模拟 Supabase 的登录（含 session_id）、实时频道、推送表，跑一遍 `review/site/parts/04-新增SQL-20261117.sql`（连跑两遍，确认可以重复执行），再逐项检查：实时广播只能发给好友/群友、被踢设备读不到聊天也不能登记推送、群消息补推不重复不漏推。注意：这里的数据库是超级用户，线上读 `auth.sessions` 的权限要看 SQL 最后那张检查表。

## 改版本号

每次改 `app.js` 都要把 `index.html` 里 3 处 `app.js?v=…` 一起改，而且**新版本号必须比旧的“大”**（自动更新靠比大小判断新旧，数字部分按数值比）：`20261118d4` → `20261118d5` → … → `20261119a`。

## 写新检查

`run.js` 里照着已有的 `test('名字', async () => { ... })` 写：
- `makeEnv({ db })` 造一个假手机；
- `env.login()` 登录；
- `env.rtFire('INSERT', 'messages', 行)` 模拟实时通道推来一条；
- `serverInsert(db, 消息)` 像线上触发器一样插入消息并更新会话；
- 用 `ok(条件, '没通过时显示的话')` 判断结果。

注意：app.js 末尾那行 `if (window.__TEST__) window.__T = {` 是给检查用的接口，别删。

## 私聊附件权限

```bash
node sql-private-attachments-test.mjs
```

这组在 PGlite 执行实际迁移和回滚，用合成会话和 Storage 操作名检查访问权限。测试包含默认关闭、历史公开文件、身份与消息匹配、精准对象路径、禁止签名与列举、缩略图、撤回、两种回滚，以及其他规则误放行时的保护。

配备隔离 Auth、PostgREST、Realtime 和真实 Storage 的预览环境中，可以运行浏览器检查。预览必须使用环回地址，并安装本迁移，在隔离库中启用私密照片写入。

```bash
CHATTER_PRIVATE_PREVIEW_URL=http://127.0.0.1:58776 node private-photo-browser.js
```

浏览器检查用三个独立会话覆盖旧图兼容、新图片发送、原图保存、陌生人拒绝、私聊和群聊转发、退群、撤回和附件管理。图片走带登录凭证的读取请求，显示用的临时地址只存于当前页面。独立导出文件中的私密图片只留提示，重要图片可在聊天中单独保存。延迟回包的判断覆盖切换聊天和账号，移动设备体验还要真机核对。

数据库和文件有可恢复备份，并确认旧客户端升级和验收后，才开启生产的私密照片写入。已有私有文件时，回滚保留读取权限并暂停新写入，新发私聊照片不会改传到公开桶。空桶回滚移除附加权限和消息字段，保留空私有桶。现有公开桶没有改动。语音、视频、普通文件和朋友圈仍走原路径。
