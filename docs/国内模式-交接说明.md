# 交接说明：让 Supabase 应用在国内网络（不开 VPN）下也能实时联机

这份说明来自 Chatter（聊天 App）的实现，已经做完并测试通过。请参照它，把滑板游戏也改成国内网络可以联机。

---

## 一、问题是什么（用户实测过）

在中国大陆不开 VPN 时：

- **能用**：Supabase 的普通 HTTPS 请求，包括数据库接口 `/rest/v1/`、登录 `/auth/v1/`、文件存储 `/storage/v1/`，以及广播的 HTTP 发送接口 `POST /realtime/v1/api/broadcast`。用户在 Safari 打开 `https://<项目>.supabase.co/rest/v1/`，能看到 `{"message":"No API key found in request"...}`，消息也能发出去。
- **不能用**：Realtime 的 WebSocket 长连接 `wss://<项目>.supabase.co/realtime/v1/websocket`。`channel.subscribe()` 的回调只会收到 `TIMED_OUT` 或 `CHANNEL_ERROR`，永远收不到 `SUBSCRIBED`。所以广播、Presence、postgres_changes 这些**接收**全都收不到。

结论：**发送没问题，问题只在接收**。思路是让接收不再依赖 WebSocket，改用 HTTP 长轮询。

不要考虑的方案：workers.dev、vercel.app、pages.dev 这类免费中转域名在国内基本都被封了，用户朋友的网络已经实测打不开；用户也不想买域名。

---

## 二、Chatter 的做法（“国内模式”）

### 1. 自动检测、自动切换

- 用 `subscribe((status, err) => ...)` 记录各个通道是否 `SUBSCRIBED`，比如 `S.rt.db`、`S.rt.user`。
- **只要有通道不是 `SUBSCRIBED`，就运行国内模式的循环**；一旦实时通道连上了（比如用户开了 VPN），就停止轮询，用回 WebSocket。全程不用用户手动切换。
- 实时通道失败时**不要弹“未授权、请运行 SQL”这类提示**。只有 `CHANNEL_ERROR` 且错误文字里有 `unauthorized`、`permission`、`denied`、`policy` 时，才是真的权限问题。
- 网络失败会反复发生，错误日志每种只记一次，避免刷屏。
- 诊断页显示黄色说明“已切换国内模式”，不要显示红叉。

### 2. 长轮询收件箱：`poll_inbox()`（关键，延迟 0.1～0.3 秒）

用户嫌“每 2 秒查一次”太慢，所以改成了长轮询：

- 客户端调用 RPC `poll_inbox(p_since, p_wait_ms)`。服务器在函数里循环：有新内容就**立刻返回**；没有的话每 0.2 秒查一次（`pg_sleep(0.2)`），最多等 2.5 秒后返回空结果。
- 客户端拿到结果后**马上再发下一个请求**，间隔 30 毫秒。
- 空闲时大约每 2.5 秒一个请求，比每 2 秒短轮询还省；有新东西时几乎是即时到达。
- Supabase 给 `authenticated` 角色设的 `statement_timeout` 是 8 秒，所以等待上限要远低于 8 秒，我们用 2.5 秒。
- 每个正在长轮询的客户端会占用 PostgREST 的一个数据库连接。几个人同时在线没问题，几十人同时在线就不合适了，游戏要注意房间人数。

客户端的要点：

- **10 秒超时**：国内网络偶尔会让请求卡住，既不成功也不报错。用 `AbortController`，加上 supabase-js 的 `.abortSignal(signal)`，10 秒没回就放弃，**放弃后立刻重发**。其他错误等 2 秒再重试。
- **页面切到后台就暂停**（`document.hidden`），回到前台时立刻重启循环。用一个递增的 `run` 编号，让旧的那轮循环自己退出，避免同时跑两个循环。
- **时间一律用服务器时间比较**，不要用手机本地时间，手机时间可能不准。

### 3. 信号信箱：`signals` 表 + `send_signal()` + `take_signals()`

用来传 WebRTC 信令（邀请、接听、ICE 候选、挂断）和“正在输入”这类短消息：

- `send_signal(p_to, p_payload)`：只能发给好友（游戏里应改成“同一房间的玩家”）。每次发送时，顺手删掉 10 分钟前没人取走的旧信号。
- 取信号时**取走即删**（`delete ... returning`），而且**只返回 1 分钟以内的**，否则对方打开 App 时会冒出早就挂断的“幽灵来电”。
- 返回结果**按 `id` 排序**，保证 offer、answer、ice 的先后顺序。
- 表开启 RLS，但**不建任何策略**，并且 `revoke all`。网页端只能通过 `security definer` 函数访问，函数只授权给 `authenticated`。
- `from_acc` 以服务器记录为准，覆盖掉信号内容里自带的 `from`，防止冒充。

### 4. 双通道发送 + 去重（必须做，否则会出 bug）

- 发送方不知道对方能不能连上实时通道，所以**每个信号同时走两条路**：HTTP 广播（`/realtime/v1/api/broadcast`，不依赖自己的 WebSocket），以及 `send_signal` 写进信箱。只要有一条成功就算发送成功。
- 每个信号都带一个**唯一编号 `sq`**，格式是 `账号:时间36进制:自增序号`。接收方用一个 Set 记住处理过的编号，重复的直接丢弃，Set 超过 600 个就裁掉一半。
- 额外保护：收到一个“邀请”，如果它的通话编号和当前正在进行的通话相同，就忽略它。否则重复的邀请会触发“对方忙线”，把正在进行的通话挂掉。
- 能连上实时通道的一方，也要每 30 秒清一次信箱，否则信号会堆在表里。重复的会被去重。

### 5. 其他功能走数据库

- 在线状态：`heartbeat(p_online)` 每 30 秒报到一次，切到后台时传 `false`。`friends_seen()` 由**服务器判断** 75 秒内报到过就算在线。
- 已读：`mark_read()` 用服务器时间记录，`peer_read()` 查询对方读到哪里。
- 新消息：`poll_inbox` 里一起返回。为防止同一时刻提交的消息被漏掉，往回多给 15 秒，客户端按 `id` 去重；只有比游标更新的消息才算“有新内容”，才会提前返回。
- **第一次轮询**时，会话列表里已有的消息只登记、不提醒，否则会把已经看过的消息又当成新消息响一次。

### 6. 测试方法

用一个假的 supabase 客户端，可以模拟三种网络：

- `window.__noWS = true`：订阅回调返回 `TIMED_OUT`，并且广播和数据库变更都不投递，模拟国内网络。
- `window.__wsStatusFail = true`：状态显示失败，但广播仍会送到，用来测试“同一个信号从两条通道同时到达”时的去重。
- 让 `poll_inbox` 永远不返回：模拟请求被卡住，验证 10 秒后能自动恢复。

已经验证通过的场景：两边都被拦、一边被拦一边正常、双通道重复到达、没运行 SQL 时自动退回旧方式、请求卡住后自动恢复。另外，原有的全部测试在正常网络下也都通过。

SQL 在本地真实的 PostgreSQL 16 上跑过，加了 `auth.uid()`、`storage`、`realtime` 的桩：可以重复执行；外人取不到别人的信号；匿名用户不能调用；过期信号不会返回；原有数据没有被改动。

## 三、用到滑板游戏上的建议

游戏和聊天不一样：**玩家位置每秒要同步 10～30 次**。数据库长轮询的延迟是 0.1～0.5 秒，而且每秒要写好几次数据库，**不适合直接用来同步位置**。

推荐的架构：

1. **数据库只做“牵线”**：大厅、房间、准备开始这些，以及 WebRTC 的 offer、answer、ICE，都用上面的“信号信箱 + 长轮询”。正常网络下优先走 Realtime，连不上时自动切到国内模式，和 Chatter 一样。
2. **连上之后，游戏数据走 WebRTC DataChannel**，玩家之间直接传，不经过 Supabase：
   - 位置、姿态用**不可靠、不排序**的通道：`ordered: false, maxRetransmits: 0`，丢一帧没关系，延迟最低。
   - 进球、技巧得分、聊天这类事件用**可靠**通道（默认设置）。
   - 4 人以内用全连接，每两个玩家之间各一条连接。
3. **ICE 服务器**：STUN 用 iPhone 5G 真机实测能用的：`stun:stun.miwifi.com:3478`、`stun:stun.hitv.com:3478`、`stun:stun.chat.bilibili.com:3478`、`stun:stun.cloudflare.com:3478`、`stun:stun.l.google.com:19302`（`stun.qq.com` 实测不通，不要用），再加 TURN 作为后备。Chatter 原来用的 Metered 账号是：
   ```
   用户名 8e04f6769d4effbe70fb66f7  密码 z8AVqW5ZnBQ0zgNV
   turn:global.relay.metered.ca:80
   turn:global.relay.metered.ca:80?transport=tcp
   turn:global.relay.metered.ca:443
   turns:global.relay.metered.ca:443?transport=tcp
   ```
   ⚠️ 【已更正】Metered 免费版官网写的是 “Free: 500 MB trial”，每月 500MB（上传加下载），不是 5GB。现在主力改用 ExpressTURN（官网：免费每月 1000GB，只支持 3478 端口的 UDP/TCP，地址 `turn:free.expressturn.com:3478?transport=udp` 和 `?transport=tcp`，账号以用户后台为准），Metered 只做备用。走中转时**不要自动降画质**，用户要求画质只能由他自己选。
4. **DataChannel 连不上时的后备**：在房间里改走数据库中转，每秒 5～10 次，客户端做插值让画面平滑，并且提示玩家“网络受限，可能有延迟”。不要因为网络问题擅自降低画质，用户明确要求画质只能由玩家自己选。
5. **SQL 要在游戏用的 Supabase 项目里运行**，也就是用户的 “games” 项目，不是 Chatter 的项目。`send_signal` 的“必须是好友”检查，要改成“必须在同一个房间”。
6. 用户最怕 bug，要求改动攒成一次交付、反复测试。会让用户执行 SQL 的地方要先告诉他，并给出完整的 SQL；GitHub 和 Supabase 的操作步骤要写机翻后的中文按钮名，并附上直接网址。

## 四、Chatter 的 SQL（参考，请按游戏的需要修改）

```sql
-- 通话信号信箱
create table if not exists public.signals (
  id         bigserial primary key,
  to_acc     text not null,
  from_acc   text not null,
  payload    jsonb not null,
  created_at timestamptz not null default now()
);
create index if not exists signals_to_idx on public.signals (to_acc, id);
alter table public.signals enable row level security;
revoke all on table public.signals from anon, authenticated;

create or replace function public.send_signal(p_to text, p_payload jsonb)
returns void language plpgsql security definer set search_path = public as $$
declare me text := public.my_acc();   -- my_acc()：通过 auth.uid() 查出自己的账号
begin
  if me is null then raise exception 'not authenticated'; end if;
  if not exists (select 1 from public.friendships where owner_acc = me and friend_acc = p_to) then
    raise exception 'not friends';    -- 游戏里改成：检查双方在同一个房间
  end if;
  if octet_length(p_payload::text) > 60000 then raise exception 'payload too large'; end if;
  delete from public.signals where created_at < now() - interval '10 minutes';
  insert into public.signals (to_acc, from_acc, payload) values (p_to, me, p_payload);
end $$;

create or replace function public.take_signals()
returns table (id bigint, from_acc text, payload jsonb, created_at timestamptz)
language plpgsql security definer set search_path = public as $$
declare me text := public.my_acc();
begin
  if me is null then return; end if;
  return query
    with d as (delete from public.signals s where s.to_acc = me
               returning s.id, s.from_acc, s.payload, s.created_at)
    select d.id, d.from_acc, d.payload, d.created_at from d
     where d.created_at > now() - interval '60 seconds' order by d.id;
end $$;

-- 长轮询收件箱：有新内容立刻返回，没有就最多等 2.5 秒
create or replace function public.poll_inbox(p_since timestamptz, p_wait_ms integer default 0)
returns jsonb language plpgsql security definer set search_path = public as $$
declare
  me       text := public.my_acc();
  since    timestamptz := coalesce(p_since, now() - interval '60 seconds');
  deadline timestamptz := clock_timestamp() + make_interval(secs => least(greatest(coalesce(p_wait_ms, 0), 0), 2500) / 1000.0);
  msgs jsonb; sigs jsonb; fresh integer;
begin
  if me is null then return null; end if;
  loop
    select coalesce(jsonb_agg(to_jsonb(m) order by m.created_at), '[]'::jsonb),
           count(*) filter (where m.created_at > since)
      into msgs, fresh
      from (select * from public.messages
             where to_acc = me and created_at > since - interval '15 seconds'
             order by created_at limit 100) m;
    with d as (delete from public.signals s where s.to_acc = me
               returning s.id, s.from_acc, s.payload, s.created_at)
    select coalesce(jsonb_agg(jsonb_build_object('id', d.id, 'from_acc', d.from_acc, 'payload', d.payload) order by d.id)
                    filter (where d.created_at > now() - interval '60 seconds'), '[]'::jsonb)
      into sigs from d;
    exit when fresh > 0 or jsonb_array_length(sigs) > 0 or clock_timestamp() >= deadline;
    perform pg_sleep(0.2);
  end loop;
  return jsonb_build_object('msgs', msgs, 'sigs', sigs);
end $$;

-- 在线状态
create table if not exists public.presence (account_id text primary key, last_seen timestamptz);
alter table public.presence enable row level security;
revoke all on table public.presence from anon, authenticated;

create or replace function public.heartbeat(p_online boolean default true)
returns void language plpgsql security definer set search_path = public as $$
declare me text := public.my_acc();
begin
  if me is null then return; end if;
  insert into public.presence (account_id, last_seen) values (me, case when p_online then now() else null end)
  on conflict (account_id) do update set last_seen = excluded.last_seen;
end $$;

create or replace function public.friends_seen()
returns table (account_id text, online boolean)
language sql stable security definer set search_path = public as $$
  select f.friend_acc, coalesce(p.last_seen > now() - interval '75 seconds', false)
    from public.friendships f left join public.presence p on p.account_id = f.friend_acc
   where f.owner_acc = public.my_acc()
$$;

-- 权限：只给登录用户
revoke all on function public.send_signal(text, jsonb)         from public, anon;
revoke all on function public.take_signals()                   from public, anon;
revoke all on function public.poll_inbox(timestamptz, integer) from public, anon;
revoke all on function public.heartbeat(boolean)               from public, anon;
revoke all on function public.friends_seen()                   from public, anon;
grant execute on function public.send_signal(text, jsonb)         to authenticated;
grant execute on function public.take_signals()                   to authenticated;
grant execute on function public.poll_inbox(timestamptz, integer) to authenticated;
grant execute on function public.heartbeat(boolean)               to authenticated;
grant execute on function public.friends_seen()                   to authenticated;
```

## 五、Chatter 客户端的核心代码（参考）

```js
// 发信号：HTTP 广播 + 数据库信箱，两条路同时发，带唯一编号 sq
let sigSeq = 0;
const sqOf = () => ME() + ':' + Date.now().toString(36) + ':' + (++sigSeq);
async function sig(peer, t, data) {
  const p = Object.assign({ t, from: ME(), sq: sqOf() }, data);
  const [a, b] = await Promise.all([
    bcast('u:' + peer, 'sig', p),                                   // POST /realtime/v1/api/broadcast，不依赖 WebSocket
    sb.rpc('send_signal', { p_to: peer, p_payload: p }).then(r => !r.error, () => false)
  ]);
  return a || b;
}
// 收信号：按 sq 去重（两条路都会送到）
const sigSeen = new Set();
function sigDup(p) { if (!p || typeof p.sq !== 'string') return false; if (sigSeen.has(p.sq)) return true; sigSeen.add(p.sq); return false; }

// 国内模式循环：只要实时通道没连上就长轮询
let fbRun = 0, fbT = 0, cursor = 0;
function fbKick() { fbRun++; clearTimeout(fbT); fbT = setTimeout(fbLoop, 50); }   // 回到前台时调用
async function fbLoop() {
  const run = fbRun; let next = 1000;
  if (document.hidden) { fbT = setTimeout(fbLoop, 3000); return; }
  try {
    if (!realtimeOk()) {
      const ctl = new AbortController(), tm = setTimeout(() => ctl.abort(), 10000);   // 卡住 10 秒就放弃
      let res; try { res = await sb.rpc('poll_inbox', { p_since: new Date(cursor || Date.now() - 60000).toISOString(), p_wait_ms: 2500 }).abortSignal(ctl.signal); }
      finally { clearTimeout(tm); }
      if (res.error) { const e = new Error(res.error.message); e.abort = /abort/i.test(res.error.message || ''); throw e; }
      handleRows(res.data);   // 更新 cursor（用服务器时间）；按 id 排序处理信号；sigDup 去重
      next = 30;              // 马上再问
    }
  } catch (e) { next = e.abort ? 30 : 2000; }   // 卡住被放弃：立刻重发；其他错误：等 2 秒
  if (run !== fbRun) return;                     // 已有新一轮循环，旧的退出
  fbT = setTimeout(fbLoop, next);
}
```
