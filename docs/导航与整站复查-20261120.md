## 如何验导航

单人可直接打开独立的 `navigation.html`，也可在 Chatter 的「应用 → 导航」进入。输入城市、地名和具体入口后，从候选中选择，查看地址和坐标。选好入口后，直接选步行、骑行或驾车，点击「计算路线」对应的按钮。可以允许本次定位，也可以手填起点。目的地链接只携带用户选定的点和名称。

1. 搜一个两地同名的地点。确认只有手动点选后才产生路线入口。改搜另一个词后，旧路线入口应消失。
2. 用实际熟悉的两个门核对标记和道路终点。Chatter 对源数据用 WGS84。地图上显示的坐标顺序是纬度、经度，给接口时按其规范使用经度、纬度。如果算路起点或终点相距所选点超过 60 米（步行、骑行）或 120 米（驾车），本版提示核对并停止画这条路线。这是本版选取的提示阈值，道路更新和同楼不同层仍要看现场。估时采用静态道路数据。
3. 地图服务不通时仍显示地点名称、原坐标和高德标记入口。高德标记明确声明 `coordinate=wgs84`，进入高德后核对标记再选路线。接入端的单次真实查询返回了上海浦东的东方明珠；另一次上海样本步行路线长 1,317.4 米，服务返回的终点距目的地约 19 米。这两次云端请求未验证实地通行或国内手机覆盖率。底图和国内网络表现按设备分别记录。[高德标记参数](https://lbs.amap.com/api/uri-api/guide/mobile-web/marker) · [路线服务及使用条件](https://routing.openstreetmap.de/about.html)
4. 双人验收需要已装候选迁移的隔离后端。在好友聊天右上角「更多 → 一起导航」选目的地并发邀请，对方点卡片接受。双方各自点共享位置。可以固定等候点和楼层备注。有人提议换入口后，原目的地保留到另一方确认。任一方可结束。接受后同行 30 分钟，双方可约定续时，最长 3 小时。只向本次参与者提供 90 秒内的新定位。锁屏丢失更新时显示最后更新时间。当前位置、会合点及等待备注只写本次同行，聊天中的邀请仅含编号。
5. 在 iPhone Safari、主屏幕及 Android 的移动网络分别实际走一次，记录城区、选的入口、地图标记、真实终点、锁屏前后更新时间和电量表现。打开后台再返回检查用户是否仍在原聊天。版本内提供路线概览，实时路况、公交时刻、后台语音逐向导航和独立的仅分享 ETA 模式仍待实现。

## 手机界面验收（20261120g）

- 首次打开显示目的地搜索和随页面加载的地理总览。总览可平移和放大，在点击「在我附近选点」或选择定位算路之前，单人页面不会请求定位。
- 放大到街道并等对应图块加载后，才能点选具体入口。搜索后有多个同名结果时，先看城市和街道，选中后可展开 GPS 坐标。主按钮根据当前选择显示「计算步行路线」等文字。
- 进入同行后，邀请、共享和等候点排在手机页靠前的位置。双方都有新定位时显示直线距离；定位误差范围重叠时提示核对入口或楼层。定位超过 90 秒会撤下相应实时标记和两人距离，已固定的等候点单独保留。
- 电脑上可并排查看地图与操作区。单人页面沿用系统主题，在 Chatter 内沿用用户所选主题与字体。街道、路线和设备实测限制详见下表。

本次界面复测通过了 Chromium 的 320、390、1024 像素布局、深浅主题、定位拒绝、未加载图块与已加载图块的点选分支。地点检索及路线接口使用受控响应。还用隔离后端的三名账号验证了结伴、等候点、换入口、退出及第三人权限，设备定位与时间推进由浏览器模拟。仓库全量与快速测试、启动更新、搜索界面、Service Worker、同行 SQL 迁移和回滚均通过。尚待实际 iPhone 在移动网络、锁屏后恢复以及实地核对入口。

## 生产只读核对和上线条件

只查目录、权限和告警。当前有 34 张 public 普通表，anon 或 authenticated 可 TRUNCATE 的 public 表为 0。authenticated 对 profiles.devices 和 profiles.kick_at 均无直接列读取权限。历史 chat-media 桶仍公开，文件上限 50 MiB，MIME 清单有 17 项。另有 11 张启用行级安全但未设策略的表；public 下可由 anon 执行的特权函数为 5 个，authenticated 为 56 个。这些计数用于后续逐项复核。泄露密码防护告警仍在，性能建议包括外键索引、重复索引和多条宽松策略。既有数据库备份任务已有产物，生产恢复演练本轮未执行。[Supabase 安全检查](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy) · [密码防护](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)

- 新接口要求有效账号及双向好友关系，并按当前会话和实际同行编号读写。私有表禁止普通客户端直接读取。接收方接受后，每个人仍需主动分享本机定位。结束或解除好友关系会删除临时会话。位置超过 90 秒停止显示；90 秒是显示有效期。期限内最后一个坐标可能仍在临时表，至同行结束或到期清理。
- 生产目录显示 pg_cron 可用但尚未安装。候选迁移在扩展可用时启用并安排每分钟删除到期同行。隔离 PostgreSQL 已验证表、权限、重复执行、前台到期清理与回滚；该隔离实例没有 pg_cron 二进制，生产调度本身将在批准后验证。回滚仅移除本功能的任务、接口、表和私有命名空间，保留可供其他任务使用的扩展。回滚会结束正在进行的同行。
- 现有备份工作流会导出业务表数据。在启用生产共享前，应在备份任务的 data-only 导出中添加 `-x "chatter_navigation_private.trips"`，核对一次新备份不含同行数据。UNLOGGED 表可以被逻辑转储。精确坐标也会按用户的请求用于定位、地图和路线提供商。先核对保留策略、迁移及回滚，再决定是否执行。
- 生产尚未安装导航接口。单人导航不依赖本次数据库变更。主分支、旧媒体桶、线上账号和聊天数据均不需要为了前端验收而更动。

迁移和回滚在 `supabase/migrations/20261120024725_chatter_navigation.sql` 与 `supabase/rollback/20261120024725_chatter_navigation.sql`。审阅页提供含检查表的 SQL。测试命令在 `tests/README.md`。整合前主分支在 Git 历史可从 `3c6d9aa` 和 `abcd1f6` 恢复。正式发布后的前端回退需使用更高资源版本号，以便已安装的 PWA 取得回退代码。

### 服务配置与真机验收

`app_config` 的可选键为 `navigation`，值是 JSON 对象。可配置 `searchUrl`（Photon 兼容 API）、`routeBase`（以下含 routed-foot、routed-bike、routed-car 三个 OSRM 子路径）及 `tiles`（含 `url`、`credit`、`creditUrl` 的 WGS84/Web Mercator XYZ 瓦片图源）。图块模板使用 `{z}`、`{x}`、`{y}`。配置会送到客户端，限使用公开的服务地址及准许展示的图源。替换图源时核对坐标系、署名和使用许可。读取失败使用内置服务。生产配置本轮未改。

iPhone 用户在国内网络的网络上实测 OSM、Carto 图块超时，Photon 和算路端点可连。天地图和 Esri 的可达性尚不能确定使用许可、街道质量及入口精度。建议现场在熟悉的门口试「在我附近选点 → 我就在入口，用这次定位」，命名后在坐标和高德标记中核对，再行走一段检查实际终点。锁屏定位、iOS 主屏幕、长时间行程与不同网络仍待验收。[用户真机记录](https://github.com/3855285335-GIF/index.html/issues/6#issuecomment-7041196133)
