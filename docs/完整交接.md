## 1. 用户是谁、在什么条件下用

- 说中文，用 **iPhone**，人在中国大陆（时区 Asia/Shanghai）。看 GitHub 和 Supabase 后台时用 **Safari 自带的中文翻译**，所以操作步骤要写“机器翻译后的中文按钮名”，并附直达网址。
- 平时会开 VPN，但要求 **Chatter 不开 VPN 也能用**。实测：不开 VPN 时，Supabase 的普通请求（数据库接口、登录、文件、发消息）能通，**实时通道（WebSocket）连不上**——所以有“国内模式”。
- 用户朋友的网络封了 `workers.dev`、`vercel.app`（实测打不开），但 `github.io` 能用，所以网站放在 GitHub Pages。用户**不想买域名**。
- 用户**没有能在国外网站付款的信用卡**：只能用免费、不绑卡的服务。
- 电脑很旧（4 GB 内存、2 GB 显存），没有 Mac。
- 用户还在别的窗口做一个 3D 滑板联机游戏（单个 HTML 文件，也用 Supabase），和 Chatter 是姐妹项目；以后还会做别的软件，打算都并进 Chatter。
- 用户非常信任 AI，只在关键时刻来找 Claude 把关；**最怕 BUG**。被不准确的说法坑过好几次（中转额度、注册地址、服务器地址），所以对“没核实就说”特别敏感。
- 现在 Chatter 大约 15 个账号（朋友小范围用）、6 个群、1253 条消息（11-19 统计）。

## 3. 用户的工作方式要求（必须遵守）

1. **全部用中文**：回复、步骤之间的进度说明、最后的总结都用中文，不出现英文句子。（用户提醒过好几次，长任务最后的总结写成英文被批评过。）
2. **想深一点，别肤浅**：交付前自己把整个使用过程走一遍，问“还缺什么”，别等用户发现。（例：浏览器上线时没有翻译、出现生硬的“429”错误页，被批评“你每次都不仔细想”；11-19 用户又说“你要为未来的长远做打算，不要只看一点点肤浅的东西”。）
3. **数字、额度、地址先查官网再说**；没查过明说“没核实 / 估计”；说错了就说“我之前说错了”。（被坑过：Metered 免费额度说成 5GB/20GB，实际 500MB；ExpressTURN 注册地址给错；服务器地址写错；Exa“每月 1 号恢复”没核实。）
4. **说清哪些只在模拟里测过、哪些要真机测**：电脑上测试通过不等于用户手机、用户网络上能用。每次交付都列“要真机确认的”。
5. **一次打包交付**，不要零碎地一会儿改一点；说了“不用重新上传”就不能反悔。
6. **直接推送到 GitHub**：用户授权了，不用等他说“传”；**永远不要让用户手动上传文件或手动合并**。
7. **数据库能自己做就自己做**（用户给了 Supabase 连接器的全部权限，11-19 说“你不能自己上传吗”）。改权限的 SQL 运行时会在用户那边弹确认框：**运行前先告诉用户“马上会弹确认框，请点同意”**；被拒或用户没点，就把 SQL 文件发给用户，附直达链接和中文按钮名。
8. **给用户的 SQL**：完整代码、直达链接 https://supabase.com/dashboard/project/uaoiqbxptnbrvkzjwguc/sql/new、机器翻译后的按钮名（右下角“Run”（运行）；弹出“Potential issue detected with your query”（检测到查询可能有问题）时点“Run this query”（运行此查询））；SQL 要能重复执行、整份在一个事务里、最后带一张中文“检查表”（每行“是/否”）。
9. **难撤销的选择要提前说**（比如建项目选哪个区），在用户动手之前。
10. **可能变的东西从一开始就放数据库**（服务器地址、账号、名单、模型名、密钥），以后改只需运行 SQL，不用更新页面。
11. **画质优先**：图片、视频不压缩；**不经用户同意不降低通话 / 视频质量来省中转额度**（“中转省流量”默认关，按钮现在隐藏）。11-19 发现发图片默认被压缩、而且切换按钮不在页面上，已改回默认原图（见第 6 节）。
12. **联网数据一开始就按省免费额度设计**：格式紧凑、变化了才发、能缓存就缓存。
13. 交付 App 时**给用户看主屏幕图标**（`icon-192.png`）。
14. 用户在不同窗口做不同项目、会在窗口之间转话：**写交接或待办之前，先读另一个窗口 / 仓库现状，确认每一步都需要、和之前说的一致**。
15. 改完先跑测试，**全部通过才推送**；反复检查。
16. 新页面一律跟随“我”里的浅色 / 深色主题和字体设置，不自己另搞一套配色；**不要做作的装饰标语**（用户觉得刻意）。

## 4. 安全红线

- **密钥不进代码、不进仓库、不进记忆**：Exa、Tavily、智谱（以及可选的 Groq、OpenAlex、GitHub）的密钥只放在数据库 `public.search_keys` 表里（开了行级安全、收回了手机端全部权限，只有服务器函数能读）。服务器函数先看环境变量，没有再读这张表，改了 1 分钟内生效。**每次提交前搜一遍仓库确认没有密钥**。
- 用户在聊天里贴过 GitHub 令牌和 Supabase `sbp_` 令牌：**不要用、不要存、不要写进任何地方**。部署服务器函数用 Supabase 连接器。
- 不在聊天里贴数据库密码、连接串。网页里只有可公开的 `sb_publishable_…` 密钥。
- **不做 VPN、不做翻墙代理、不做“通用网页代理”**（把任意网站整页通过我们的服务器转发给手机）。用户 11-19 问过 VPN，已明确拒绝。现在的原网页是手机自己直接打开的；服务器只看对方网站的响应头判断能不能嵌入。简洁阅读是服务器取回正文后洗干净再给手机（只有文字和图片，不运行对方脚本）。也不推荐具体的免费 VPN。
- 不做冒充真实网站、收集账号密码的页面；仿冒网址要提醒用户而不是放行。
- 服务器函数取网页时只取公开网站：拒绝本机、内网地址、我们自己的数据库接口；跳转到这些地址也拒绝；查域名解析结果必须全是公网地址（线上实测可用）。

## 5. 用户想要的东西（愿景和全部需求）

### 5.1 大方向
- 把其他软件都并进 Chatter：**浏览器（自己的搜索）→ 音乐 → 导航**，外加**“今天去哪”**（挑废弃的、小众的地方）。应用页布局用户定了“**小组件 + 图标格子**”（方案三）。用户担心并进来会不会有风险、怎么布局，需要 AI 给方案。
- 想要一个**不买域名的“转发站”**（让国内网络更稳；还没做，workers.dev / vercel.app 在朋友网络被封，不能用）。
- App 要快、接近同步、能装到手机上。

### 5.2 浏览器 / 搜索（第 1 步，主体已完成）
- 自己的搜索、自己的结果页、页面干净简单，**由用户决定什么排前面**（置顶网站、不看的网站、隐藏营销号、干净页面优先），不是给别的浏览器换皮。
- 目标是**看到尽可能多的东西**，包括“深网”内容；数据源要最强的，在国内被墙也没关系（服务器在东京）。
- **只用免费来源**（不付费、不绑卡）：Exa 为主、Tavily 备用；不限每人次数。
- 外文内容自动翻成中文；中文词可以“翻成英文再搜”。
- 打不开的网页按原因说清楚、给对应按钮；仿冒网址红色提醒。
- **11-19：原网页要在 App 里显示，不能跳到 Safari**；iPhone、安卓、电脑都要考虑；为长远打算。

### 5.3 朋友圈（11-19）
- 能不让某些人看：每条动态选“公开 / 私密 / 部分可见 / 不给谁看”，发出去后能改；好友资料页“朋友圈权限”：不让对方看我的、不看对方的。
- “不是好友的只能看见点赞，不能看见评论”——**Claude 的理解（像微信）**：一条动态下面只看得到自己好友写的评论（加上作者的、自己的、回复自己的）；点赞所有能看到这条的人都看得到。**这个理解还没让用户确认过**；不对的话改数据库函数 `can_see_comment`。

### 5.4 计划中、还没开始
- 音乐：通过自己的搜索找免费、公开的音频来听。
- 导航：自己的界面，最好有卫星图（要找免费、不绑卡、国内能用的地图数据，还没调研）。
- “今天去哪”：推荐废弃、小众的地方（数据来源还没定）。

## 8. 架构

### 8.1 前端加载
- `index.html` 里的内联脚本先显示启动图，再从多个来源抢着下载 Supabase 库（本地 `vendor/` 优先），下载过的存在手机里，第二次打开不联网。
- `app.js?v=版本号` 用 `defer` 加载；`search.js?v=同一个版本号` 等用到才加载。
- 测试用接口：`app.js` 末尾 `if (window.__TEST__) window.__T = {…}`，**别删**。

### 8.2 数据流
- 启动时一个 `bootstrap()` 请求拿回自己的资料、好友、会话（最近 200 个）、聊天对象资料、待处理的好友申请。
- 发消息：本地先显示（转圈），后台写 `messages` 表；数据库触发器更新双方的 `conversations`（预览、时间、未读）；同时走实时广播让对方秒收（广播里不带消息正文，对方收到后去数据库核对）。
- 每个用户一个私有广播频道 `u:账号`（消息提示、通话信号、正在输入、已读、上线下线）；群消息另有一个频道订阅“我所在的群”。数据库函数 `rt_can_send()` 规定只能发给自己、好友、同群的人。
- 全局在线频道已停用（以前任何人都能看所有人在线、能冒充）；在线状态靠好友之间的上下线广播 + `friends_seen` 心跳。

### 8.3 国内模式（不开 VPN 也能用）
- 只要实时通道没连上就自动切换，连上了自动切回，用户不用管。
- **长轮询** `poll_inbox()`：服务器有新消息或信号立刻返回，没有就最多等几秒（现在窗口约 6 秒，上限 8 秒），手机拿到结果马上发下一个；包括群消息。
- **通话信号**：同时走 HTTP 广播和数据库信箱（`send_signal` / `take_signals`），用编号去重；信箱取走即删，超过 1 分钟不返回（防幽灵来电）。
- 在线状态：变化了才报，页面关闭时用 `fetch keepalive` 报离线；约 40 秒报到一次，服务器按 75 秒内报到算在线。已读：`mark_read`（服务器时间）+ `peer_read`。
- 代价：每台国内模式的手机占一个数据库连接，几个人没问题，几十人同时在线不合适。11-15 起轮询频率提高过一倍（列表页约 3 秒一个小请求），要留意流量。
- 姐妹项目滑板游戏也按这个思路做了国内联机（旧分支 `source` 里有 `docs/国内模式-交接说明.md`）。

### 8.4 通话
- STUN（iPhone 5G 真机实测能用）：`stun.miwifi.com`、`stun.hitv.com`、`stun.chat.bilibili.com`、`stun.cloudflare.com`（都是 3478 端口）、`stun.l.google.com:19302`；`stun.qq.com` 实测不通，不用。
- TURN 中转：两台手机能直连时不走中转、不花额度。中转服务器**只从数据库 `app_config` 的 `ice` 读**（11-19 GPT 去掉了代码里写死的默认值），读不到用手机里上次存的。现在配了 2 个（ExpressTURN 主力、Metered 备用）。换账号或服务商只需要改数据库，不用更新页面。
- “中转省流量”：开了以后走中转时视频约 300kbps、分辨率减半，语音约 24kbps；**默认关、按钮现在隐藏**（用户要求不经同意不降画质）。
- 已知：用户实测过一次两家中转都能拿到中转地址，另有一次不开 VPN 时全部失败，原因没查明。

### 8.5 推送（`chatter-push`）
- 手机在“我 → 通知”开启 → 浏览器给出推送地址 → `push_save()` 存进 `push_subs`。
- 发消息 / 打电话 / 加好友后，**发送方**请求 `chatter-push`；函数核对登录凭证和会话（被踢的设备拒绝），调用数据库 `push_job()` 决定推不推（必须是好友 / 群友、对方不在线或没读、同一条只推一次、群消息按“消息 + 成员”记）；然后自己用 WebCrypto 加密（RFC 8291）和签名（RFC 8292），只发给苹果 / 谷歌 / 火狐 / 微软的推送服务；地址失效（404/410）就删。
- 签名密钥第一次运行自动生成，存在 `push_keys`（谁都读不到）。
- 安卓 Chrome 的网页推送走谷歌 FCM，国内网络大概率收不到（没真机验证）。

### 8.6 搜索 / 浏览器（`search.js` + `chatter-search`）
- **服务器函数的操作**：`search`（网页 / 图片 / 视频 / 新闻 / 深挖）、`read`（简洁阅读，可看互联网档案馆存档）、`versions`（历史版本）、`translate`（翻译一组段落）、`frame`（原网页能不能嵌进 App）、`usage`（本月用量）、`ping`（检查，不用登录；`probe:'dns'` 自测域名解析）。
- 网页 / 新闻 / 视频先用 Exa，用完自动换 Tavily；图片先用 Tavily，再加维基共享资源的图。发现某家用完了 6 小时内不再试。同样的搜索 24 小时内用缓存（按人分开，防止别人从快慢推出你搜过什么）。
- 深挖：维基百科（简体摘要）、互联网档案馆、论文库 OpenAlex（不带密钥会被限流）、GitHub、Hacker News，全部免费。
- 搜索规则（存在账号里，换手机也在）：置顶网站、不看的网站、隐藏营销号、干净页面优先、网页先用哪家、外文自动翻译、**先显示原网页还是先简洁阅读**；默认名单（营销号、干净网站、要登录的网站、知名网站）在数据库 `app_config` 的 `search` 里。
- 简洁阅读：服务器取网页（最多 3MB、国内网站的 GBK 编码也能读），提取正文，按白名单洗一遍，手机上再洗一遍；首页、目录页给链接列表；打不开时按原因（找不到网站、被删、要登录、限流、太慢、对方出错）给不同按钮；档案馆限流自动等 1.5 秒重试一次。
- **原网页（11-19）**：先问服务器 `frame`（只看响应头 X-Frame-Options / CSP frame-ancestors，不取正文）→ 能嵌就在 App 里用网页框（沙盒：不能跳走整个 App、不能弹对话框）显示，手机自己去打开网站；不让嵌的自动换简洁阅读并说明；要登录的网站给“用浏览器打开（能用你的登录）”，点了才跳；服务器取不到时照样试着嵌，下面提示“看不到内容？换简洁阅读”；“×”一步关掉（网页里点过的链接会在浏览器历史里留下记录，代码会一步步退回去），“‹”先在网页里后退。聊天里的网址也走这里。
- 翻译：智谱免费模型 `glm-4-flash-250414`（备用 `glm-4.7-flash`，模型名在数据库里，可以填几个，前一个太忙或下线就换下一个），同时最多 3 组；智谱按国内规定拒绝的段落拆小重试，还不行交给 Groq（可选，没填密钥就跳过）；同一段 30 天内不重翻（服务器存一份，手机也记一份）。
- 仿冒网址提醒：和 57 个知名网站只差几个字母时红色提醒，第一个按钮是“去真的××”。

### 8.7 后台小助手（sw.js，版本 4.2）
- 带版本号的程序文件和 `vendor/` 存手机，第二次打开不用下载；页面联网优先、2.5 秒没回来先用存着的；聊天和朋友圈图片存手机最多 300 张；弹推送通知、点通知打开对应聊天（`#c=`、`#g=`、`#call=`）。

### 8.8 版本号和自动更新
- 改了 `app.js` 要把 `index.html` 里 **3 处** `app.js?v=…` 一起改，新版本号必须“更大”（按数字部分比较：`20261119b` → `20261119c` → … → `20261120a`）。测试里用的假新版本号是 `20991231a1`，正式版本别超过它。
- 回到前台时（最多 10 分钟一次）检查网上的版本号；有新版先提示再换，换完回到原来那一页并提示“已更新到新版本”；同一个新版 1 小时内最多自动换 2 次。

## 9. 数据库

### 9.1 表（public）
| 表 | 用途 |
|---|---|
| `profiles` | 账号资料。公开字段：id、account_id、nickname、avatar_url、signature、created_at、bg_url、cover_url、bubble_color；**私密字段**（11-19 起别人读不到，自己通过 `bootstrap()` / `my_kick_at()` 读）：moments_seen_at、mutes、devices、kick_at |
| `friend_requests` / `friendships` | 好友申请（只能把状态改成“拒绝”，接受走 `accept_friend_request`）/ 好友关系（每人一行；带 remark 备注、hide_moments 不让他看、skip_moments 不看他） |
| `messages` / `conversations` | 消息 / 每人每个会话一行（预览、时间、已读时间、未读数、置顶、草稿），由触发器维护 |
| `chat_groups` / `chat_group_members` / `group_invites` / `group_kicks` / `group_notices` / `group_files` / `group_calls` / `group_call_members` | 群聊全套 |
| `moments` / `moment_likes` / `moment_comments` / `moment_mentions` / `moment_views` / `moment_audience` | 朋友圈；`moment_audience`（11-19）存“部分可见 / 不给谁看”的名单，**只有作者读得到**，发表或修改时由触发器从 `visible_to` / `hidden_from` 挪进来 |
| `signals` | 通话信号信箱（国内模式） |
| `presence` | 在线心跳 |
| `push_subs` / `push_log` / `push_keys` | 推送登记 / 去重记录 / 签名密钥 |
| `stickers` | 我的表情（每人最多 500） |
| `chat_backgrounds` / `user_mutes` / `user_devices` | 聊天背景 / 免打扰 / 登录设备 |
| `app_config` | 可变配置：`ice`（通话中转）、`search`（搜索和翻译的全部设置与名单）。**谁都能读**，所以不能放密钥 |
| `search_keys` / `search_cache` / `search_usage` / `search_prefs` | 搜索密钥（只有服务器能读）/ 缓存 / 用量计数 / 每人的搜索规则 |
| `keepalive_state` | 保活记录 |

### 9.2 关键函数（大多是 security definer）
- 身份和会话：`my_acc()`（当前账号；11-19 起会话被踢就返回空）、`session_alive()`（登录凭证里的会话还在不在，且属于这个人）、`my_kick_at()`、`kick_others()`。
- 启动和消息：`bootstrap()`、`mark_read()`、`peer_read()`、`poll_inbox()`、`send_signal()` / `take_signals()`、`heartbeat()`、`friends_seen()`、`send_group_msg()`。
- 好友：`send_friend_request(p_to)`（带锁，两人同时互加不出错）、`accept_friend_request()`、`remove_friendship()`、`set_remark()`。旧版 `send_friend_request(发送者, 接收者, 名字)` 还在但已收回所有权限（以前不用登录就能冒充别人发申请）。
- 群：`invite_to_group`、`accept_group_invite`、`group_invite_approve`、`join_group_by_link`、`ensure_group_link`、`kick_member_v2`、`set_group_admin`、`transfer_group_owner`、`set_group_mute_all`、`set_group_member_mute`、`set_group_notice`、`set_member_title`、`group_call_*` 等。
- 朋友圈：`can_see_moment(动态, 账号)`（11-19 起手机上只能问自己）、`can_see_comment()`、`moment_audience_ok()`、`moment_is_open()`（转发前问“是不是对全部好友公开”）、`set_moment_perm()`。
- 推送：`push_job()`（外壳）→ `push_job_base` / `push_job_edit` / `push_job_gmsg`、`push_save`、`push_gone`、`push_vapid` / `push_set_vapid`。
- 实时权限：`rt_can_send()`。搜索：`search_bump()`（计数，北京时间算“每天”“每月”）。保活：`keepalive()`。版本：`chatter_schema()` 返回 8。

### 9.3 规则要点
- 全部表开了行级安全；`messages`、`conversations`、`signals`、`moments`、`moment_comments` 另有一道“会话必须还活着”的限制规则；11-19 起 `my_acc()` 本身也查会话，所以被踢设备连调用函数都不行（用真实会话模拟验证过：假会话号读消息 0 条）。
- 存储桶 `chat-media`：公开读（看图不用登录）、单个文件 50MB、**只能传到自己的文件夹 `账号/文件名`（只能一层）**、只收常见图片、音视频、PDF、文本和普通文件（网页文件当文本存，不能当网页打开）。
- 实时通道里 `profiles` 只发公开字段。
- 手机端不能清空整张表（收回了 TRUNCATE）；触发器函数手机调不了。

### 9.4 迁移和撤销
- 11-19 起每次改动写成 `supabase/migrations/时间_名字.sql` + `supabase/rollback/同名.sql`。现有：GPT 的 6 份（表权限、资料隐私、上传归属、函数权限、文件类型、好友申请状态）+ Claude 的朋友圈权限。**都已在线上运行**（Supabase 的迁移记录里名字是 `chatter_moment_privacy`、`chatter_security_repair_1119`）。
- 给用户运行的版本放在 `review/site/parts/04-新增SQL-日期-名字.sql`（可重复执行、带检查表），并加到审阅页列表。
- 11-19 以前的 SQL 汇总在 `review/all-sql.sql`，旧的分版本 SQL 在旧分支 `source` 的 `sql/` 里。
- 测试里用过 `pg_net` 扩展（从数据库发请求测线上函数），用完要删掉（现在已删）。

## 13. 已知问题、风险、没核实的事

- 网页技术的天花板：网站自己禁止被嵌入的（谷歌、知乎、B 站、推特等大网站常这样），任何网页 App 都没法原样显示，只能简洁阅读或跳浏览器。只有原生 App 的内置浏览器能做到（第 14 节）。
- iPhone 不给网页框用别的网站的登录（第三方 Cookie），所以要登录的网站在 App 里显示的是没登录的样子。
- Chromium 里删掉网页框后它留下的历史记录不会清掉，所以“×”是一步步退回去的；Safari 的行为没真机试过。
- 旧版手机（20261119b 以前、还没自动更新的）：读不到“被踢时间”、接受好友申请可能失败；重开 App 自动更新后就好。
- 改成默认原图后存储用得更快；免费版文件上限没重新核实。
- 规则里有些地方是 `my_acc()` 每行调用一次，现在每次还会查一次会话；数据量大了会慢，以后改成 `(select my_acc())` 写法。
- 国内模式每台手机占一个数据库连接，几十人同时在线不合适。
- 好友之间仍能在广播内容里冒充“另一个好友”（频道权限只能管能不能发给这个人，管不到内容里写的发送者）；陌生人已经发不了。
- 不开 VPN 时：外文网站的图片、YouTube、互联网档案馆在国内可能打不开（简洁阅读的文字是东京服务器取的，不受影响）。
- 中转服务器：有一次不开 VPN 时两家都连不上，原因没查明；ExpressTURN 没写运营公司，哪天停了要换。
- 安卓推送在国内大概率收不到（没验证）。
- OpenAlex 不带密钥会被限流（可以免费申请一个，放 `search_keys`）。
- 仓库的自动部署（`.github/workflows/deploy-search.yml`）需要仓库密钥 `SUPABASE_ACCESS_TOKEN`，**现在没设**，推送后不会自动部署，要用 Supabase 连接器部署。

## 15. 两个 AI 怎么配合

1. 开工前：`git pull --rebase` 拿最新 `main`；读 `AGENTS.md` 第 6 节和这份第 12 节；`git log --oneline -20` 看对方最近做了什么。
2. 推送：小改动跑完检查直接推 `main`；大改动或可能撞车的，在自己的分支做（Claude 用 `claude/…`，ChatGPT 用 `gpt/…`），做完**自己**在最新 `main` 上重跑全部检查再合并，不留给用户合并。
3. 同一时间不要两个人改同一块（比如都改朋友圈）；提交说明写清楚改的是哪一块。
4. 最后合进 `main` 的负责把版本号改成比线上大的新号。
5. 数据库改动：迁移 + 撤销脚本 + 给用户的可重复执行版本（带检查表），并写进审阅页；运行了就在 `AGENTS.md` 第 6 节和这份第 12 节写明。
6. 服务器函数改了要部署，部署后用 `{"op":"ping"}` 确认线上版本号。
7. 做完一件事：更新 `AGENTS.md` 第 6 节、这份第 12 节，在 `review/site/parts/05-今日改动-日期.md` 写改动清单（中文、用户能看懂的话），代码副本（`review/site/parts/01/02/06/07`）换成最新的。
8. 对方的代码也要审：GPT 11-19 的改动 Claude 是逐个读过、跑过全部检查才合并的；以后互相也这样。

## 16. 操作手册

- **部署服务器函数**：用 Supabase 连接器的“部署函数”（名字 `chatter-search` 或 `chatter-push`，入口 `index.ts`，verify_jwt 关）。部署后检查：`POST https://uaoiqbxptnbrvkzjwguc.supabase.co/functions/v1/chatter-search`，内容 `{"op":"ping","probe":"dns"}`，返回的 `v` 是新版本号、`dnsApi` 是 `works`。如果只能从数据库发请求，临时开 `pg_net` 扩展，用完删掉。
- **运行 SQL**：能自己运行就自己运行（改权限的先提醒用户点同意）；运行后用只读查询核对检查表，再用 `set local role authenticated` + 设置登录凭证的方式模拟真实用户查一遍（注意：模拟时不能往临时表写，结果先存变量）。
- **改 app.js 的流程**：改代码（保留 CRLF）→ 改 `index.html` 里 3 处版本号 → `npm test` + 其余检查 → 搜一遍密钥 → 推送 → 更新文档。
- **加 / 换密钥**：`insert into public.search_keys (name, value) values ('EXA_API_KEY', '…') on conflict (name) do update set value = excluded.value, updated_at = now();`（名字还有 `TAVILY_API_KEY`、`ZHIPU_API_KEY`、`GROQ_API_KEY`、`OPENALEX_API_KEY`、`GITHUB_TOKEN`）。密钥本身别写进聊天总结、仓库、记忆。
- **换通话中转**：改 `app_config` 里 `key='ice'` 的 `value`（格式 `{"turn":[{"name":…,"urls":…,"username":…,"credential":…}]}`），不用更新页面。
- **改搜索设置 / 名单 / 翻译模型**：改 `app_config` 里 `key='search'` 的 JSON（`order`、`img_order`、`farms`、`clean`、`direct`、`popular`、`tr_order`、`tr_models`、`tr_par`、各种每天上限），1 分钟内生效。
- **回滚**：`supabase/rollback/` 下同名脚本倒着运行；朋友圈权限的撤销会把设过“不给谁看”的动态改成仅自己可见（不把内容露给被排除的人）。代码回滚用 `git revert`，并把版本号改成更大的新号（不能变小，否则自动更新不认）。
- **看用量**：`select pg_size_pretty(pg_database_size(current_database()));` 和 `storage.objects` 的文件数、大小；搜索用量在 `search_usage`（`uid` 全 0 的行是全站每月合计）。
